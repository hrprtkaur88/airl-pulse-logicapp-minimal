# AI-Ready Leader project concept reference

Use this file as the LLM-readable reference for the report’s purpose, output design, and commercial intent. The original concept slide can remain an archival source, but this Markdown file should be preferred during report writing.

## How to use this reference

- Use this file to keep the report focused on client-ready insight, not just data visualization.
- Use it to guide the balance between data, benchmark comparison, narrative interpretation, and recommended follow-up opportunities.
- Use it to ensure the output supports scalable generation across major client accounts.
- Do not copy slide text directly unless a short phrase is useful.

## Project purpose

The report combines individual-level AI Ready Leader client data with Korn Ferry benchmarks to generate a client-ready narrative and data output for priority accounts.

The goal is to use existing assessment data to tell a sharper story about each client’s current leader population, reveal targeted needs, and create immediate expansion conversations grounded in evidence.

## Three-layer model

### 1. Client data: what we already know

The input data includes:

- Individual-level AI Ready Leader assessment results.
- Existing population data for client accounts.
- Cuts by level, function, segment, and geography when available.
- Data should only be used where participation supports directional interpretation.

Report implication:
Use the uploaded workbook as the sole source for scores, gaps, rankings, heatmaps, n sizes, demographic charts, and client names. Do not invent population cuts or demographics.

### 2. Benchmark overlay: what it means in context

The benchmark layer compares client results to AI Ready Leader benchmarks to:

- Surface strengths.
- Surface gaps and areas of risk.
- Identify patterns across leader populations.
- Translate findings into commercially relevant insight.

Report implication:
Do not simply present benchmark gaps. Interpret what the benchmark pattern means for AI-ready leadership, deployment, enablement, and follow-up action.

### 3. Automated output: what client teams receive

The output should:

- Generate a client-ready narrative and data summary.
- Provide a storyline, visuals, and implications.
- Equip teams with targeted follow-up opportunities.
- Scale insight delivery across major accounts.

Report implication:
Every section should help the reader move from data to implication. Visuals should support a storyline, not sit apart from it.

## Commercial outcome

The commercial outcome is to help client teams use existing assessment data to:

- Tell a sharper story about the current leader population.
- Reveal targeted needs.
- Create immediate expansion conversations grounded in evidence.
- Connect AI readiness patterns to development, deployment, coaching, succession, and broader Human + AI transformation opportunities.

## Design principles for report generation

### Be data-grounded

All data, visuals, gaps, rankings, heatmaps, demographic summaries, and n sizes must come from the uploaded workbook.

### Be benchmark-aware

Scores should be interpreted relative to the AI Ready Leader benchmark. Gaps should be described as percentage-point differences to the benchmark.

### Be commercially useful

Narrative should help a client team understand what to do next. Avoid generic commentary that does not lead to a follow-up conversation.

### Be client-specific

Use the client’s data pattern and current AI/digital strategy context. Do not reuse prior-client narrative.

### Be scalable

The workflow should work across many client workbooks with minimal back-and-forth. Template sections and required elements should not be omitted.

## Section-specific use

### Hero
State the headline insight from the data. The hero should tell the client what the overall pattern means, not just what the report contains.

### About the Data
Show the assessment population, coverage, and directional caveats. Include participant count, time period, year distribution, level distribution, region mix, and assessment type.

### Executive Narrative
Translate the overall result into a client-ready leadership story. Include the strongest advantage, watch area, external AI strategy context, and commercial implication.

### Interpretive Storyline
Connect the data into a strategic story. The top two insight cards should carry the most important implications. Four expandable cards should add nuance.

### Benchmark Comparison
Show the client’s six responsibility pattern against benchmark and explain whether results show advantage, near-benchmark performance, or a readiness-building need.

### Underlying Leadership Signals
Use construct-level results to add behavioral precision. Explain why the surfaced constructs matter for AI transformation.

### Heatmaps
Use heatmaps to show where readiness should be accelerated or enabled by function, level, and region. When a section has enough subgroup rows for comparison, include three narrative callouts and an Interpretation Guide; when subgroup data is limited, use the limited-data behavior defined in output_contract.md.

### Recommended Follow-up Opportunities
Use the output to create next-step opportunities that are data-specific, client-specific, and commercially actionable.

## Guardrails

- Do not treat the output as a generic data dashboard.
- Do not omit narrative sections just because the data looks straightforward.
- Do not overclaim precision from small n sizes.
- Do not state that the sample represents the full organization.
- Do not allow the report to become a simple listing of high and low scores.
- Every section should answer: what does this mean and what should the client do next?
